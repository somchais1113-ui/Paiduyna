## หน้า Dashboard (Landing)

เมื่อเปิดแอป จะแสดงหน้า Dashboard ก่อนเข้าสู่ตารางเต็ม สรุปข้อมูลตามเวลาจริง ได้แก่ นาฬิกาและวันที่ รอบรถไฟชานเมืองปกติเที่ยวถัดไป (อ้างอิงเที่ยวขึ้นจากหัวลำโพงไปฉะเชิงเทรา) และรอบ Airport Rail Link เที่ยวถัดไป (พญาไทไปสุวรรณภูมิ เลือกตารางวันธรรมดา/วันหยุดอัตโนมัติ) พร้อมเวลานับถอยหลังก่อนออก ทุกอย่างอัปเดตทุกวินาที กดปุ่มลูกศรด้านขวาบนเพื่อเข้าสู่หน้าหลัก โดยตัดปุ่มซ้ำด้านล่างออกแล้ว

มีปุ่มวัดความเร็วปัจจุบันของผู้ใช้ (แตะเพื่อเปิด) อ่านค่าจาก Geolocation API แปลงเป็น กม./ชม. เลือกให้แตะเปิดเองแทนการขอตำแหน่งทันทีที่โหลด เพื่อไม่รบกวนผู้ใช้ หากต้องการให้หน้านี้แสดงครั้งเดียวต่อการเปิดเบราว์เซอร์ สามารถเพิ่มการจำสถานะด้วย sessionStorage ได้

สถานะการเชื่อมต่อบนหัวเว็บถูกย่อจากข้อความเป็นจุดสีเขียวกะพริบวางไว้ท้ายโลโก้ (เปลี่ยนเป็นสีเหลืองเมื่อออฟไลน์) เพื่อลดความรก

## ระบบค้นหาลานจอดรถ

ฟีเจอร์นี้ทำงานแบบไฮบริด 3 ชั้น เพื่อให้ใช้ได้ทั้ง Offline และค้นหาสด โดยยึดหลักว่าแสดง "ตำแหน่ง" ลานจอด ไม่ใช่สถานะที่ว่างแบบเรียลไทม์ เพราะไม่มี Feed จำนวนช่องจอดว่างของสถานี SRT และ ARL

1. ชั้นข้อมูลนิ่ง อ่านลานจอดที่ยืนยันแล้วจาก `data/parking.json` แคชผ่าน Service Worker ใช้ได้ขณะไม่มีเน็ต
2. ชั้นค้นหาตามชื่อสถานี ปุ่มค้นหาสร้างลิงก์ Google Maps จากชื่อสถานีต้นทาง ไม่พึ่งพิกัดในไฟล์
3. ชั้นค้นหาสด ปุ่มหาที่จอดใกล้ตำแหน่งฉัน ขอ Location แล้วค้น `amenity=parking` รอบผู้ใช้ในรัศมี 800 เมตรผ่าน Overpass API เรียงตามระยะทาง และมีปุ่มนำทางรายรายการ หากค้นไม่สำเร็จจะมีปุ่มสำรองเปิด Google Maps

### แผนที่ Google แบบฝัง

การ์ดลานจอดฝังแผนที่ Google ผ่าน iframe แบบไม่ต้องใช้ API Key (`maps.google.com/...&output=embed`) โหลดเมื่อผู้ใช้กดวิธีค้นหาเท่านั้น เพื่อความเป็นส่วนตัวและประหยัด กดใกล้สถานีต้นทางจะแสดงแผนที่รอบสถานี ส่วนใกล้ตำแหน่งฉันจะแสดงแผนที่รอบพิกัดผู้ใช้ พร้อมลิงก์เปิดใน Google Maps เต็ม

ข้อจำกัดที่ควรทราบ วิธี `output=embed` เป็นวิธีที่ไม่มีเอกสารทางการรองรับ Google อาจเปลี่ยนได้ในอนาคต แผนที่ต้องใช้อินเทอร์เน็ต และ iframe ของ Google จะตั้งคุกกี้ของตนเอง หากต้องการเสถียรกว่าให้พิจารณา Google Maps Embed API แบบมี Key (ต้องจำกัด Referrer) หรือฝังแผนที่ OpenStreetMap ด้วย Leaflet

### ปุ่มลัดและการจัดวาง

มีแถบปุ่มลัด (แบบ Sticky อยู่บนสุดขณะเลื่อน) สำหรับกระโดดไปยังหัวข้อหลัก วางแผนการเดินทาง ตารางเดินรถ ลานจอดรถ จุดเชื่อมต่อ และหมายเหตุ ส่วนหมายเหตุการใช้บริการถูกย้ายไปไว้ล่างสุดและพับเก็บเป็นแบบแตะเพื่อเปิด เพื่อลดความรกของหน้าหลัก

### เพิ่มลานจอดที่ยืนยันแล้ว

แก้ไฟล์ `data/parking.json` เติมรายการในฟิลด์ `lots` ของแต่ละสถานี หากใส่ `lat` และ `lng` ปุ่มนำทางจะพาไปยังพิกัดนั้นโดยตรง ถ้าไม่ใส่ ระบบจะค้นหาด้วยชื่อลานจอดแทน

```json
{
  "stations": {
    "latkrabang": {
      "lots": [
        {
          "name": "อาคารจอดแล้วจร ARL ลาดกระบัง",
          "type": "park_and_ride",
          "lat": 13.7270,
          "lng": 100.7510,
          "note": "ค่าบริการและเวลาทำการโปรดตรวจสอบกับผู้ให้บริการ"
        }
      ]
    }
  }
}
```

`type` รับค่า `park_and_ride`, `public` หรือ `private` ไฟล์นี้ถูกเพิ่มไว้ใน App Shell ของ `sw.js` แล้ว หากแก้ไฟล์นี้ควรขึ้นเลขเวอร์ชัน `CACHE` ใน `sw.js` เพื่อให้เครื่องผู้ใช้โหลดข้อมูลใหม่

### ต้อง Deploy บน Vercel

ส่วนตารางเดินรถยังเปิดแบบ Static ได้ แต่ Strava API ต้องใช้ Server Function ดังนั้นการ์ดวิ่งจริงจะทำงานเมื่อ Deploy บน Vercel หรือแพลตฟอร์มที่รองรับ Node.js Functions เท่านั้น หากเปิดผ่าน GitHub Pages การ์ดจะแสดงสถานะว่ายังไม่พร้อมเชื่อมต่อ

### ขั้นตอนตั้งค่า Strava ครั้งแรก

1. เปิดหน้า API Settings ในบัญชี Strava และสร้าง Application
2. ตั้ง `Authorization Callback Domain` เป็นโดเมน Vercel ของเว็บ เช่น `paiduyna.vercel.app` โดยไม่ใส่ `https://` และไม่ใส่ path
3. ใน Vercel Project ไปที่ Storage แล้วสร้าง Blob Store แบบ `Private` และเชื่อมกับ Project นี้
4. ใน Vercel Project Settings > Environment Variables เพิ่มค่า:

```text
STRAVA_CLIENT_ID
STRAVA_CLIENT_SECRET
STRAVA_SETUP_KEY
STRAVA_SCOPE=read,activity:read_all
```

Vercel Function จะได้รับสิทธิ์เข้าถึง Private Blob Store ที่เชื่อมกับ Project โดยอัตโนมัติ ในการทดสอบนอก Vercel อาจต้องกำหนด `BLOB_READ_WRITE_TOKEN` เอง หากกำหนด Redirect URI เอง ให้เพิ่ม:

```text
STRAVA_REDIRECT_URI=https://ชื่อโดเมนของคุณ/api/strava/callback
```

5. Deploy เว็บไซต์ใหม่
6. เปิดลิงก์นี้ด้วยเบราว์เซอร์ของเจ้าของเว็บ:

```text
https://ชื่อโดเมนของคุณ/api/strava/connect?key=ค่า_STRAVA_SETUP_KEY
```

7. ล็อกอิน Strava และกดอนุญาต เมื่อสำเร็จ ระบบจะเก็บ Access Token และ Refresh Token ใน Private Vercel Blob
8. กลับหน้า Landing แล้วกดปุ่ม `↻` บนการ์ดวิ่ง

`STRAVA_SETUP_KEY` ป้องกันไม่ให้บุคคลอื่นเริ่มขั้นตอน OAuth แล้วนำบัญชีของตนมาเขียนทับบัญชีที่ใช้แสดงบนเว็บไซต์ จึงควรตั้งเป็นข้อความยาวและห้ามเผยแพร่

### การอัปเดตข้อมูล

- ดึงข้อมูลเมื่อเปิดหน้า Landing
- กด `↻` เพื่อดึงใหม่ได้ทันที
- ขณะหน้าเว็บเปิดอยู่ ระบบตรวจใหม่ทุก 10 นาที
- Server Function ใช้ Cache ระยะสั้น 60 วินาทีเพื่อลดการเรียก Strava API ซ้ำ
- Access Token มีอายุจำกัด ระบบจะ Refresh ให้อัตโนมัติและบันทึก Refresh Token ตัวล่าสุดกลับไปยัง Private Blob

### สถานะบนการ์ด

- `กิจกรรมล่าสุดของวันนี้` เมื่อดึงข้อมูลสำเร็จ
- `วันนี้ยังไม่ได้วิ่ง` เมื่อบัญชีเชื่อมแล้วแต่ไม่มีกิจกรรมวิ่งของวันนี้
- `รอการเชื่อมบัญชี` เมื่อยังไม่ได้ทำ OAuth
- `ยังไม่พร้อมใช้งาน` เมื่อ Server Function หรือ Strava API มีปัญหา

### ความเป็นส่วนตัว

การนำสถิติการวิ่งขึ้น Landing Page ทำให้ผู้เข้าชมเว็บไซต์เห็นข้อมูลดังกล่าวแบบสาธารณะ แม้กิจกรรมต้นทางใน Strava จะตั้งเป็น Only You ก็ตาม หากใช้ scope `activity:read_all` จึงควรแสดงเฉพาะค่าที่เจ้าของเว็บยินยอมเผยแพร่ ซึ่ง Build นี้ตั้งใจตัดข้อมูลเส้นทางและพิกัดออกแล้ว

## v37 วางแผนข้ามระบบ และโครงข่าย M-MAP 2

Build นี้เพิ่มการวางแผนเดินทางข้ามระบบ ต่อจากรถไฟและ ARL ไปยัง BTS, MRT หรือรถสาธารณะอื่น ออกแบบเป็น 2 ชั้นที่แยกหน้าที่กันชัดเจน

### ชั้นที่ 1 วางเส้นทางจริง (ต้อง Deploy บน Vercel)

- Vercel Function `api/routes/transit.js` เรียก Google Directions API โหมด transit
- รับต้นทาง/ปลายทางเป็นพิกัดหรือชื่อสถานที่ แล้วคืนเส้นทางเป็น leg ย่อย เดิน/ขึ้นรถไฟฟ้า/ต่อรถ
- รองรับเฉพาะสายที่เปิดให้บริการจริงตามข้อมูลฝั่ง Google
- API Key อยู่ใน `GOOGLE_DIRECTIONS_API_KEY` ฝั่ง Vercel เท่านั้น (ใช้ key เดียวกับ Places ได้ หากเปิด Directions API ให้ key นั้น ระบบจะ fallback ไปใช้ `GOOGLE_PLACES_API_KEY` อัตโนมัติ)
- Cache ฝั่ง Vercel 120 วินาที
- การ์ด `วางแผนข้ามระบบ` บนหน้าหลัก: เลือกตั้งต้นจากสถานีปลายทางที่เลือกในตาราง หรือจากตำแหน่งปัจจุบัน แล้วพิมพ์จุดหมาย
- เปิดผ่าน GitHub Pages หรือพรีวิวในเครื่องจะแสดงสถานะว่าต้อง Deploy บน Vercel

### ชั้นที่ 2 โครงข่าย M-MAP 2 (ใช้ Offline ได้)

- ไฟล์ `data/network.json` เก็บจุดเชื่อมต่อและสายอนาคตแบบกรอกเอง แคชผ่าน Service Worker
- การ์ด `จุดเชื่อมต่อการเดินทาง` แสดงผลจากไฟล์นี้ (มี fallback ใน HTML หากโหลดไม่ได้)
- ส่วน `เส้นทางในอนาคต (M-MAP 2)` แสดงสายที่ยังไม่เปิดบริการ พร้อมป้ายสถานะ เปิดบริการ/ก่อสร้าง/ในแผน อย่างชัดเจน
- สายอนาคตเป็นข้อมูลประกอบ ไม่ถูกนำไปวางเป็นเส้นทางที่แนะนำ เพราะ Directions API รู้จักเฉพาะสายที่เปิดจริง

### ตั้งค่า Google Directions

1. เปิด Directions API และสร้างหรือใช้ API Key เดิมที่เปิด Directions API
2. ใน Vercel Project Settings > Environment Variables เพิ่ม `GOOGLE_DIRECTIONS_API_KEY` (หรือใช้ `GOOGLE_PLACES_API_KEY` เดิมที่เปิด Directions API ด้วย)
3. Redeploy แล้วทดสอบจากการ์ด `วางแผนข้ามระบบ`

### เพิ่มหรือแก้ข้อมูลโครงข่าย

แก้ `data/network.json` เติมรายการใน `interchanges` (จุดเชื่อมต่อ) หรือ `futureLines` (สายอนาคต) ฟิลด์ `atStation` ต้องตรงกับ id สถานีใน `index.html` รายการที่ทำเครื่องหมาย `needsReview: true` ควรตรวจสอบกับประกาศทางการก่อนเผยแพร่ หากแก้ไฟล์นี้ควรขึ้นเลข `CACHE` ใน `sw.js`

### ที่มาข้อมูลโครงข่าย

- แผน M-MAP 2 กรมการขนส่งทางราง กระทรวงคมนาคม (หลายสายยังอยู่ระหว่างศึกษาหรือก่อสร้าง)
- เส้นทางจริงและตารางเดินรถขนส่งสาธารณะ: Google Directions

## v42–v44 แจ้งเตือนแบบ Push ทำงานได้แม้ปิดแอป (รองรับ Vercel Hobby)

ระบบนี้แจ้งเตือนขบวนล่วงหน้า 10 นาทีผ่าน Web Push จริง ต่างจากปุ่ม "แจ้งเตือนก่อนออก" เดิมที่ต้องเปิดแท็บแอปค้างไว้ ปุ่ม "แจ้งเตือนแม้ปิดแอป" ยังทำงานได้เมื่อปิดแท็บหรือปิดแอปแล้ว ตราบใดที่ตั้งค่า Redis, VAPID และ GitHub Actions ครบ

### เหตุผลที่ v44 เปลี่ยน Scheduler

Vercel Hobby อนุญาต Cron Job ได้เพียงวันละครั้ง ดังนั้น schedule เดิม `*/5 * * * *` ใน `vercel.json` จะทำให้ Deploy ล้มเหลว เวอร์ชัน v44 จึงเอา Vercel Cron ออก และใช้ GitHub Actions เรียก API ทุกประมาณ 5 นาทีแทน

### สถาปัตยกรรม

- **`api/push/vapid-public-key.js`** คืน VAPID Public Key ให้หน้าเว็บใช้ตอน Subscribe
- **`api/push/subscribe.js`** รับ Subscription + ข้อมูลขบวน แล้วบันทึกลง Upstash Redis พร้อม TTL
- **`api/push/unsubscribe.js`** ลบการแจ้งเตือนทั้งหมดที่ผูกกับอุปกรณ์นั้น
- **`api/push/cron.js`** ตรวจรายการที่ถึงเวลา ส่ง Push ผ่าน `web-push` และรองรับ retry สำหรับข้อผิดพลาดชั่วคราว
- **`lib/redis.js`** สร้าง Redis client กลาง รองรับทั้ง `UPSTASH_REDIS_REST_*` และ `KV_REST_API_*`
- **`.github/workflows/push-reminder-cron.yml`** เรียก `/api/push/cron` ทุก 5 นาที โดยส่ง `Authorization: Bearer ...`
- **`sw.js`** รับ push event แล้วแสดง Notification
- **`vercel.json`** ไม่มี `crons` แล้ว จึง Deploy บน Hobby ได้

### ตั้งค่าบน Vercel

1. ไปที่ Vercel Marketplace แล้วติดตั้ง **Upstash for Redis** เชื่อมกับโปรเจกต์ จากนั้น Redeploy หนึ่งครั้ง ระบบรองรับตัวแปรทั้งสองรูปแบบต่อไปนี้โดยอัตโนมัติ
   - `UPSTASH_REDIS_REST_URL` และ `UPSTASH_REDIS_REST_TOKEN`
   - หรือ `KV_REST_API_URL` และ `KV_REST_API_TOKEN` สำหรับฐานเดิมที่ถูกย้ายมา Upstash
2. สร้าง VAPID Keys ในเครื่องที่มี Node.js
   ```bash
   npx web-push generate-vapid-keys
   ```
3. ใน Vercel Project Settings > Environment Variables เพิ่ม
   - `VAPID_PUBLIC_KEY` = Public Key
   - `VAPID_PRIVATE_KEY` = Private Key และเปิด Sensitive
   - `VAPID_SUBJECT` = อีเมลติดต่อ เช่น `mailto:you@example.com`
   - `CRON_SECRET` = ค่าสุ่มยาวอย่างน้อย 32 ตัวอักษร
4. Redeploy โปรเจกต์หลังเพิ่ม Environment Variables

ตัวอย่างสร้าง secret ใน Terminal:

```bash
openssl rand -hex 32
```

### ตั้งค่าบน GitHub

เข้า Repository > **Settings > Secrets and variables > Actions > New repository secret** แล้วเพิ่ม 2 ค่า

- `CRON_URL` = URL Production เต็ม เช่น `https://ชื่อโปรเจกต์.vercel.app/api/push/cron`
- `CRON_SECRET` = ค่าเดียวกับ `CRON_SECRET` บน Vercel แบบตรงทุกตัวอักษร

จากนั้นตรวจว่าไฟล์ `.github/workflows/push-reminder-cron.yml` อยู่บน default branch แล้วไปที่แท็บ **Actions > Push reminder scheduler > Run workflow** เพื่อทดสอบด้วยตนเอง ผลที่ถูกต้องควรเป็น JSON ที่มี `"status":"ok"`

### เช็กลิสต์ทดสอบ

1. Vercel Deploy ต้องผ่านโดยไม่ขึ้นข้อความ Hobby cron limit
2. เปิด `https://โดเมนของคุณ/api/push/cron` ตรงๆ ต้องได้ `401 Unauthorized`
3. Run workflow จาก GitHub Actions ต้องสำเร็จ
4. ตั้งแจ้งเตือนขบวนที่ออกมากกว่า 10 นาที แล้วปิดเว็บ
5. ตรวจ Upstash ว่ามี key ชื่อขึ้นต้น `reminder:` และรอ Push Notification

### ข้อจำกัดที่ควรทราบ

- **iOS ต้อง Add to Home Screen ก่อน** Safari/iOS รองรับ Web Push สำหรับเว็บแอปที่เพิ่มเข้าหน้าจอโฮมและเปิดจากไอคอนนั้น
- **เวลาไม่เป๊ะวินาที** GitHub Actions ตั้งรอบสั้นสุดได้ 5 นาทีและอาจเริ่มช้ากว่ากำหนดได้ จึงควรคาดหวังความคลาดเคลื่อนประมาณ 5 นาทีหรือมากกว่าเล็กน้อย
- **Scheduled workflow ต้องอยู่บน default branch** และ repository สาธารณะที่ไม่มีความเคลื่อนไหวนานอาจถูก GitHub ปิด schedule อัตโนมัติ ให้เปิดกลับจากแท็บ Actions
- **Repository ส่วนตัวมีโควตา Actions** งานทุก 5 นาทีใช้จำนวน workflow runs สูง ควรตรวจโควตาของบัญชี
- รับสมัครแจ้งเตือนล่วงหน้าไม่เกิน 48 ชั่วโมง และต้องตั้งก่อนเวลาแจ้งอย่างน้อย 10 นาที
