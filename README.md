## หน้า Dashboard (Landing)

เมื่อเปิดแอป จะแสดงหน้า Dashboard ก่อนเข้าสู่ตารางเต็ม สรุปข้อมูลตามเวลาจริง ได้แก่ นาฬิกาและวันที่ รอบรถไฟชานเมืองปกติเที่ยวถัดไป (อ้างอิงเที่ยวขึ้นจากหัวลำโพงไปฉะเชิงเทรา) และรอบ Airport Rail Link เที่ยวถัดไป (พญาไทไปสุวรรณภูมิ เลือกตารางวันธรรมดา/วันหยุดอัตโนมัติ) พร้อมเวลานับถอยหลังก่อนออก ทุกอย่างอัปเดตทุกวินาที กดปุ่มลูกศรด้านขวาบนเพื่อเข้าสู่หน้าหลัก โดยตัดปุ่มซ้ำด้านล่างออกแล้ว

มีปุ่มวัดความเร็วปัจจุบันของผู้ใช้ (แตะเพื่อเปิด) อ่านค่าจาก Geolocation API แปลงเป็น กม./ชม. เลือกให้แตะเปิดเองแทนการขอตำแหน่งทันทีที่โหลด เพื่อไม่รบกวนผู้ใช้ หากต้องการให้หน้านี้แสดงครั้งเดียวต่อการเปิดเบราว์เซอร์ สามารถเพิ่มการจำสถานะด้วย sessionStorage ได้

สถานะการเชื่อมต่อบนหัวเว็บถูกย่อจากข้อความเป็นจุดสีเขียวกะพริบวางไว้ท้ายโลโก้ (เปลี่ยนเป็นสีเหลืองเมื่อออฟไลน์) เพื่อลดความรก

## ระบบค้นหาลานจอดรถ

ฟีเจอร์นี้ทำงานแบบไฮบริด 3 ชั้น เพื่อให้ใช้ได้ทั้ง Offline และค้นหาสด โดยยึดหลักว่าแสดง "ตำแหน่ง" ลานจอด ไม่ใช่สถานะที่ว่างแบบเรียลไทม์ เพราะไม่มี Feed จำนวนช่องจอดว่างของสถานี SRT และ ARL

1. ชั้นข้อมูลนิ่ง อ่านลานจอดที่ยืนยันแล้วจาก `data/parking.json` แคชผ่าน Service Worker ใช้ได้ขณะไม่มีเน็ต
2. ชั้นค้นหาตามชื่อสถานี ปุ่มค้นหาสร้างลิงก์ Google Maps จากชื่อสถานีต้นทาง ไม่พึ่งพิกัดในไฟล์
3. ชั้นค้นหาสด ปุ่มหาที่จอดใกล้ตำแหน่งฉัน ขอ Location แล้วค้น `amenity=parking` รอบผู้ใช้ในรัศมี 800 เมตรผ่าน Overpass API เรียงตามระยะทาง และมีปุ่มนำทางรายรายการ หากค้นไม่สำเร็จจะมีปุ่มสำรองเปิด Google Maps

### แผนที่ Google แบบฝัง

การ์ดลานจอดฝังแผนที่ Google ผ่าน iframe แบบไม่ต้องใช้ API Key (`maps.google.com/...&output=embed`) โหลดเมื่อผู้ใช้กดวิธีค้นหาเท่านั้น เพื่อความเป็นส่วนตัวและประหยัด กดใกล้สถานีต้นทางจะแสดงแผนที่รอบสถานี ส่วนใกล้ตำแหน่งฉันจะแสดงแผนที่รอบพิกัดผู้ใช้ พร้อมลิงก์เปิดใน Google Maps เต็ม

ข้อจำกัดที่ควรทราบ วิธี `output=embed` เป็นวิธีที่ไม่มีเอกสารทางการรองรับ Google อาจเปลี่ยนได้ในอนาคต แผนที่ต้องใช้อินเทอร์เน็ต และ iframe ของ Google จะตั้งคุกกี้ของตนเอง หากต้องการเสถียรกว่าให้พิจารณา Google Maps Embed API แบบมี Key (ต้องจำกัด Referrer) หรือฝังแผนที่ OpenStreetMap ด้วย Leaflet

### ปุ่มลัดและการจัดวาง

มีแถบปุ่มลัด (แบบ Sticky อยู่บนสุดขณะเลื่อน) สำหรับกระโดดไปยังหัวข้อหลัก วางแผนการเดินทาง ตารางเดินรถ ลานจอดรถ จุดเชื่อมต่อ และหมายเหตุ ส่วนหมายเหตุการใช้บริการถูกย้ายไปไว้ล่างสุดและพับเก็บเป็นแบบแตะเพื่อเปิด เพื่อลดความรกของหน้าหลัก

### เพิ่มลานจอดที่ยืนยันแล้ว

แก้ไฟล์ `data/parking.json` เติมรายการในฟิลด์ `lots` ของแต่ละสถานี หากใส่ `lat` และ `lng` ปุ่มนำทางจะพาไปยังพิกัดนั้นโดยตรง ถ้าไม่ใส่ ระบบจะค้นหาด้วยชื่อลานจอดแทน

```json
{
  "stations": {
    "latkrabang": {
      "lots": [
        {
          "name": "อาคารจอดแล้วจร ARL ลาดกระบัง",
          "type": "park_and_ride",
          "lat": 13.7270,
          "lng": 100.7510,
          "note": "ค่าบริการและเวลาทำการโปรดตรวจสอบกับผู้ให้บริการ"
        }
      ]
    }
  }
}
```

`type` รับค่า `park_and_ride`, `public` หรือ `private` ไฟล์นี้ถูกเพิ่มไว้ใน App Shell ของ `sw.js` แล้ว หากแก้ไฟล์นี้ควรขึ้นเลขเวอร์ชัน `CACHE` ใน `sw.js` เพื่อให้เครื่องผู้ใช้โหลดข้อมูลใหม่

ระบบไม่ส่ง Token, แผนที่วิ่ง, พิกัดเริ่มต้น หรือพิกัดสิ้นสุดไปยังหน้าเว็บ

### ต้อง Deploy บน Vercel

ส่วนตารางเดินรถยังเปิดแบบ Static ได้ แต่ Strava API ต้องใช้ Server Function ดังนั้นการ์ดวิ่งจริงจะทำงานเมื่อ Deploy บน Vercel หรือแพลตฟอร์มที่รองรับ Node.js Functions เท่านั้น หากเปิดผ่าน GitHub Pages การ์ดจะแสดงสถานะว่ายังไม่พร้อมเชื่อมต่อ

### ขั้นตอนตั้งค่า Strava ครั้งแรก

1. เปิดหน้า API Settings ในบัญชี Strava และสร้าง Application
2. ตั้ง `Authorization Callback Domain` เป็นโดเมน Vercel ของเว็บ เช่น `paiduyna.vercel.app` โดยไม่ใส่ `https://` และไม่ใส่ path
3. ใน Vercel Project ไปที่ Storage แล้วสร้าง Blob Store แบบ `Private` และเชื่อมกับ Project นี้
4. ใน Vercel Project Settings > Environment Variables เพิ่มค่า:

```text
STRAVA_CLIENT_ID
STRAVA_CLIENT_SECRET
STRAVA_SETUP_KEY
STRAVA_SCOPE=read,activity:read_all
```

Vercel Function จะได้รับสิทธิ์เข้าถึง Private Blob Store ที่เชื่อมกับ Project โดยอัตโนมัติ ในการทดสอบนอก Vercel อาจต้องกำหนด `BLOB_READ_WRITE_TOKEN` เอง หากกำหนด Redirect URI เอง ให้เพิ่ม:

```text
STRAVA_REDIRECT_URI=https://ชื่อโดเมนของคุณ/api/strava/callback
```

5. Deploy เว็บไซต์ใหม่
6. เปิดลิงก์นี้ด้วยเบราว์เซอร์ของเจ้าของเว็บ:

```text
https://ชื่อโดเมนของคุณ/api/strava/connect?key=ค่า_STRAVA_SETUP_KEY
```

7. ล็อกอิน Strava และกดอนุญาต เมื่อสำเร็จ ระบบจะเก็บ Access Token และ Refresh Token ใน Private Vercel Blob
8. กลับหน้า Landing แล้วกดปุ่ม `↻` บนการ์ดวิ่ง

`STRAVA_SETUP_KEY` ป้องกันไม่ให้บุคคลอื่นเริ่มขั้นตอน OAuth แล้วนำบัญชีของตนมาเขียนทับบัญชีที่ใช้แสดงบนเว็บไซต์ จึงควรตั้งเป็นข้อความยาวและห้ามเผยแพร่

### การอัปเดตข้อมูล

- ดึงข้อมูลเมื่อเปิดหน้า Landing
- กด `↻` เพื่อดึงใหม่ได้ทันที
- ขณะหน้าเว็บเปิดอยู่ ระบบตรวจใหม่ทุก 10 นาที
- Server Function ใช้ Cache ระยะสั้น 60 วินาทีเพื่อลดการเรียก Strava API ซ้ำ
- Access Token มีอายุจำกัด ระบบจะ Refresh ให้อัตโนมัติและบันทึก Refresh Token ตัวล่าสุดกลับไปยัง Private Blob

### สถานะบนการ์ด

- `กิจกรรมล่าสุดของวันนี้` เมื่อดึงข้อมูลสำเร็จ
- `วันนี้ยังไม่ได้วิ่ง` เมื่อบัญชีเชื่อมแล้วแต่ไม่มีกิจกรรมวิ่งของวันนี้
- `รอการเชื่อมบัญชี` เมื่อยังไม่ได้ทำ OAuth
- `ยังไม่พร้อมใช้งาน` เมื่อ Server Function หรือ Strava API มีปัญหา

### ความเป็นส่วนตัว

การนำสถิติการวิ่งขึ้น Landing Page ทำให้ผู้เข้าชมเว็บไซต์เห็นข้อมูลดังกล่าวแบบสาธารณะ แม้กิจกรรมต้นทางใน Strava จะตั้งเป็น Only You ก็ตาม หากใช้ scope `activity:read_all` จึงควรแสดงเฉพาะค่าที่เจ้าของเว็บยินยอมเผยแพร่ ซึ่ง Build นี้ตั้งใจตัดข้อมูลเส้นทางและพิกัดออกแล้ว
